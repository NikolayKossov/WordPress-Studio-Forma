# Как разобраться в проекте

Это учебный проект, который нужно запустить и самостоятельно пройти перед собеседованием.

1. Прочитай README и запусти Docker. В `.env` задай свои локальные пароли. Эти настройки не попадут в Git.
2. Открой главную и `/wp-admin/`. В Pages найди Start: контент хранится в базе WordPress, а начальные данные находятся в `content/demo.json`.
3. Открой header.php, index.php и footer.php: это каркас страницы. В Settings → Studio FAQ измени ответ и проверь главную. Контент FAQ переживает смену темы, потому что хранится плагином.
4. Обнови текст и проверь сайт на телефоне. Зафиксируй результат скриншотами.
5. Выполни инструкцию PLUGINS.md и SEO.md. Там явно отмечено, что дополнительные плагины пока не настроены.
6. Пройди QA.md, создай issue и PR по примеру BRIEF.md.

## Что объяснить на собеседовании

- Чем тема отличается от плагина и почему контент хранится отдельно от оформления.
- Как безопасно обновлять текст и проверять результат.
- Для чего нужны проверка прав, nonce, sanitize_text_field и esc_html; почему shortcode возвращает HTML, а не печатает его.
- Что уже проверено и что ещё предстоит проверить. Не называй подготовленные шаблоны задач реальным командным опытом.

## Изменения через редактор и Git

Git хранит исходники темы, плагина и fixtures, но не текущую базу WordPress. Изменения Site Editor могут перекрывать файлы темы. Перед передачей сохрани нужные шаблоны в репозиторий через экспорт темы/копирование кода и проверь на чистой установке. При повторном импорте существующий контент не перезаписывается: новые редакторские изменения не теряются. Для новой версии демо обновляй fixtures осознанно.

## Мини-словарь

Theme — тема; child theme — дочерняя тема; template — шаблон; pattern — готовая группа блоков; slug — часть URL; staging — тестовая копия; acceptance criteria — критерии приёмки; pull request — запрос на проверку изменений.
